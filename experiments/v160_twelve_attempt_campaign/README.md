## 运行命令

PowerShell，工作目录 `D:\zgyidong`：

```powershell
$v160Python = 'D:\zgyidong\experiments\v152_error_repair_campaign\.venv\Scripts\python.exe'
$v160Campaign = 'D:\zgyidong\experiments\v160_twelve_attempt_campaign\campaign.py'
& $v160Python -B $v160Campaign audit
& $v160Python -B $v160Campaign prepare-next
```

- `init`：首次冻结来源、候选和时间窗口；重复运行只审计，不重置额度或截止时间。
- `audit`：只读核对哈希、历史约束、最高实报、剩余次数、数学上限及当前决定。
- `search`：先处理固定两次总量探针；此后执行场景与全剩余预算模拟，保存可复现结果。不会上传或占用额度。
- `prepare-next`：返回尚待反馈的文件，或生成下一份合法探针；只剩一次时转入最终合并。
- `record`：录入真实反馈并返回 TP、组计数、整数上限、冠军、余额和继续/停止决定；不会自动生成下一份文件。
- `prepare-final`：比较计数确定合并和模型辅助合并，生成可用 CSV，同时报告后者的精确 TP 范围、最差可行成绩和有限场景条件期望。

录分形式（占位符必须换成真实信息）：

```powershell
& $v160Python -B $v160Campaign record `
  --probe-id probe01_aux05 `
  --attempt-id '<本次真实提交的唯一标识>' `
  --score '<实际六位成绩>' `
  --submitted-at '<实际带时区时间，例如2026-09-14T16:00:00+08:00>' `
  --evidence '<用户反馈来源；若用录入时间代理，必须明确说明>'
```

真正重复提交必须用新的 attempt ID，每次都计入额度。重复录入同一 attempt ID 幂等。平台失败用 `--failed`，省略 `--score`，计一次并暂停。未知文件、变更哈希、分数冲突和超时均不能冒充合法反馈。

`--out` 为测试/隔离目录的全局参数，须放在子命令之前。不要新建目录来绕过账本。所有测试反馈只写临时目录。

## 候选与策略

冻结 92 个独立工单动作：A=75 新增，B=3 删除＋2 替换，C=8 删除＋3 替换＋1 新增。完整历史约束确定 A 中恰好 17 真。A 上限 0.939221，A＋B 上限 0.942463，A＋B＋C 上限 **0.949427**；均为理想选择上限，不能理解为真实胜率。

C 仅取 V158 中因 `nonpositive_conditional_utility` 被排除、但未被历史方程证伪的动作；当前基线重新验证，按两模型等权后的 `2E(deltaTP)-0.945 deltaP` 降序排序，再按工单/删除节点/新增节点打破并列，每工单一项。已有历史排除、已兑现收益和来源覆盖规则不改变。

前两份分别从固定冠军独立生成。第 3—11 次查询可来自任何计数已知的组：A 使用四种原有排序的全部切点及补集；B、C 小组枚举全部非空真子集。探针可携带不冲突、在保守反馈范围内仍提高该次成绩的计数确定组。

三个模型场景各默认生成 256 个满足**全部历史＋新反馈约束**的配置。A 用弱 RRF 秩先验；B、C 用 CatBoost、V38、等权混合温度 2。方法为逐动作因子加 Gumbel 扰动的约束 MAP，不是精确后验抽样，也不是已经校准的线上成功概率。重复配置的出现频率只属于这个有限近似。

先保留信息量最高的 24 个查询，每个用 256 个共同随机场景模拟到保留的最终一次。后续模拟采用当前信息量最高的 64 个合法查询和当前最终候选库；真实反馈到来后重新生成候选与场景。这是完整剩余深度的**有限库近似滚动模拟**，不是全动作空间的全局最优搜索。

所有实际候选的合法反馈、最终文件 TP 上下界、可达上限均由整数求解器独立复核。抽样漏掉的分支依旧允许被真实反馈接受；新一轮按新约束重新生成场景。超时退回精确可完成的单组查询；若精确查询也未完成，暂停审计。

确定合并使用已知组的分式整数集合打包，禁止重叠组重复计收益；报告的最优性限于计数已知的完整组。模型辅助合并比较有限配置中的候选子集，报告精确最差/最好分数和条件期望，不以单个 MAP 配置当作真标签。
